IDEARM is a desktop IDE for x86 Assembly, made for students. You create a project, write your program, and press
one key to build, run, debug or package it. This is the first release.

## Download

| System | File | What to do |
|---|---|---|
| Windows 10/11 (64-bit) | `IDEARM-1.0.0-windows-x64.msi` | Double-click it. It installs for your user only, so it needs no administrator rights, and adds IDEARM to the Start menu and the desktop. |
| Windows, no install | `IDEARM-1.0.0-windows-x64-portable.zip` | Unzip it anywhere and run `IDEARM\IDEARM.exe`. |
| Ubuntu / Debian (64-bit) | `IDEARM-1.0.0-linux-x64.deb` | `sudo apt install ./IDEARM-1.0.0-linux-x64.deb`. It also installs DOSBox, NASM, binutils and GDB. |
| Other Linux (64-bit) | `IDEARM-1.0.0-linux-x64.tar.gz` | Extract it and run `IDEARM/bin/IDEARM`. Needs GTK 3 (`libgtk-3-0`), which every desktop has. |

Every package carries its own Java runtime: you do not install Java. Each one also contains `idearm-cli`, the
command line, next to the application.

To check a download, compare it against `SHA256SUMS.txt`:

```bash
sha256sum --check SHA256SUMS.txt
```

```powershell
Get-FileHash .\IDEARM-1.0.0-windows-x64.msi -Algorithm SHA256
```

### Windows warns about an unknown publisher

The installer is not signed with a paid certificate, so Windows SmartScreen shows "Windows protected your PC".
Choose **More info → Run anyway**. The checksum above tells you the file is the one this page published.

## The tools IDEARM drives

IDEARM never contains or downloads TASM or MASM: they are proprietary, so you register the copy you already have
(**Help → Tool Doctor... → Add Tools Folder...**).

| You want to build | You need |
|---|---|
| 16-bit DOS programs | Your TASM + TLINK, or MASM 6.11 (`ML.EXE`, the 16-bit `LINK.EXE` and, on Linux, `DOSXNT.EXE`), and DOSBox |
| 32/64-bit Windows programs | NASM, GNU ld and GDB, for example from [MSYS2](https://www.msys2.org/) |
| 64-bit Linux programs | NASM, GNU ld (binutils) and GDB |

On Windows, install [DOSBox 0.74-3](https://www.dosbox.com/) (IDEARM prefers it, and also supports DOSBox-X and
DOSBox Staging), and the native tools with MSYS2:

```powershell
pacman -S --needed mingw-w64-ucrt-x86_64-nasm mingw-w64-ucrt-x86_64-binutils mingw-w64-ucrt-x86_64-gdb
```

On Ubuntu or Debian the `.deb` already asks apt for `dosbox`, `nasm`, `binutils` and `gdb`.

## What IDEARM 1.0.0 does

- **Builds and runs 16-bit DOS programs** with TASM or MASM inside DOSBox, without a DOSBox window during the
  build. The program runs from a copy of your project, and DOSBox is locked (secure mode) so a program cannot
  reach the rest of your disk.
- **Builds, runs and debugs 32/64-bit Windows programs and 64-bit Linux programs** with NASM, GNU ld and GDB.
- **Debugs visually**: breakpoints, stepping, registers and flags, call stack, watches and a memory dump. DOS
  programs run in a built-in 8086 emulator that reads the keyboard you type in the IDE and stops on the line where
  a program fails (division by zero, an unsupported instruction, a string with no `$`).
- **Knows Assembly while you write**: highlighting, completion, hover help for instructions, registers and
  numbers, go to definition, references, and warnings such as a program that never returns to DOS.
- **Opens old sources**: UTF-8 and Windows-1252 files are read and saved back in the same format, with the
  encoding shown in the status bar.
- **Speaks English and Spanish**, switchable while it runs, with light and dark themes.

Start with **File → New Project...**, or open one of the examples in the source repository (`examples/hello`,
`examples/hello-input`, `examples/hello64-nasm`). The [user guide](../user-guide.md) explains every workflow, and
the [troubleshooting guide](../troubleshooting.md) explains each message.

## Known limitations

- The built-in emulator has no DOS file services and no graphics; debug those programs with Turbo Debugger or
  CodeView (`[debug] backend = "external"`).
- On Linux, a program debugged with GDB reads an empty keyboard; run it with `Ctrl+F5` when it needs input.
- Native programs link only `kernel32` on Windows.
- macOS is not tested, and there is no packaged build for it.
- The Windows installer and the Linux packages are not signed.
