IDEARM 2.0 turns the debugger, the editor and the built-in help into tools a student can lean on all the way
through a course. The debugger now works inside the IDE for every new DOS project, the editor marks mistakes as
you type, and a new Academic Center explains 298 x86 instructions, the registers, the syntax of each assembler and
the DOS and BIOS services, in English and Spanish.

## Download

| System | File | What to do |
|---|---|---|
| Windows 10/11 (64-bit) | `IDEARM-2.0.0-windows-x64.msi` | Double-click it. It installs for your user only, so it needs no administrator rights, and adds IDEARM to the Start menu and the desktop. It replaces IDEARM 1.0 if you have it. |
| Windows, no install | `IDEARM-2.0.0-windows-x64-portable.zip` | Unzip it anywhere and run `IDEARM\IDEARM.exe`. |
| Ubuntu / Debian (64-bit) | `IDEARM-2.0.0-linux-x64.deb` | `sudo apt install ./IDEARM-2.0.0-linux-x64.deb`. It also installs DOSBox, NASM, binutils and GDB. |
| Other Linux (64-bit) | `IDEARM-2.0.0-linux-x64.tar.gz` | Extract it and run `IDEARM/bin/IDEARM`. Needs GTK 3 (`libgtk-3-0`), which every desktop has. |

Every package carries its own Java runtime: you do not install Java. Each one also contains `idearm-cli`, the
command line, next to the application.

To check a download, compare it against `SHA256SUMS.txt`:

```bash
sha256sum --check SHA256SUMS.txt
```

```powershell
Get-FileHash .\IDEARM-2.0.0-windows-x64.msi -Algorithm SHA256
```

## Upgrading from 1.0

Your projects open as they are: the `idearm.toml` format did not change. What changed is a default, and that is why
this is version 2:

- **New DOS projects debug in IDEARM's built-in 8086 emulator** (`[debug] backend = "emu8086"`), where stepping,
  registers, flags, memory, watches and breakpoints all work inside the IDE. In 1.0 the default was
  `external`: Turbo Debugger or CodeView in a DOSBox window, where the IDE's step buttons could not do anything.
- **A project created with 1.0 keeps the debugger it saved.** To move it to the built-in emulator, open
  **Project → Properties...** and choose it under **Debugger**. Programs that use DOS file services or graphics
  still need Turbo Debugger or CodeView, as before.

## What is new

### A debugger that works inside the IDE

- **Pause (`F6`)** stops a program stuck in a loop and shows the line it is on.
- The line about to run is **highlighted in the editor**, and the call stack can be navigated.
- A **DISASSEMBLY** panel shows the machine instructions from where the program stands, and the register table
  gains a **binary column**, grouped in nibbles.
- Breakpoints can be added and removed while a program is paused, and disabled breakpoints show as hollow rings.
- Every control follows what the chosen debugger can really do: a debugger that only launches a program replaces
  the panels with an explanation instead of buttons that do nothing.
- The debugger is chosen in **New Project** and in **Project Properties**.

### An editor that checks while you type

- A mistyped instruction such as `MUV AX, 1` gets a **red wavy underline** a moment after you stop typing, and
  hovering it suggests the right one (*Did you mean MOV?*).
- Invalid 16-bit addressing, such as `[bx+bp]` or `[ax]`, is marked with the reason.
- The warnings that used to wait for a build now appear while you type, in a Problems group of their own that never
  hides what the assembler reported.
- Real instructions from x87, MMX, SSE, AVX and system code are no longer marked as unknown in 32 and 64-bit
  projects.

### The Academic Center

**Help → Academic Assistance** (or the book icon in the Activity Bar) opens a reference that works offline:

- **298 instructions** in 18 families, with their forms, operands, flags, CPU requirements and examples, and a
  note when the built-in emulator cannot run one.
- **Registers**, with the 64/32/16/8-bit family of each one and what happens to the rest when you write a part.
- **Syntax and operators** of MASM, TASM and NASM, including the four meanings of `:` and the difference between
  `mov ax, var` and `mov ax, [var]` in each assembler.
- **DOS and BIOS services** (`INT 21h`, `INT 10h`, `INT 16h`) with their inputs, outputs and buffer layouts, and the
  CPU exceptions.
- **Concepts and nine guided learning paths**, from reading one instruction to debugging a complete program.
- Search in English or Spanish, by name, alias or idea ("carry", "acarreo", "extra segment", "stack").
- Hover in the editor explains the instruction, register, symbol or number under the pointer, and gives your own
  macros and labels priority over an instruction with the same name.

### Projects and builds

- **INCLUDE files work.** An `.inc` next to your sources, or in a declared include folder, is found, copied into the
  DOS build, and its errors point back to the right file.
- **Main file:** **Project → Properties** lets you pick the file Run starts, and build only that file.
- The New Project dialog grows with its content, so the Create button is never pushed off screen.

### A redesigned workbench

- A consistent light and dark theme across the workbench, dialogs, menus and editor pop-ups.
- A welcome screen with the next steps, guided empty panels, and a new set of icons.
- An optional minimap in the editor.

### Fixes

- A program that prints in a loop no longer freezes the IDE; the Output panel keeps the last 1 MB.
- GDB sessions no longer hang when GDB fails to start or exits, and closing a session never blocks.
- Stopping the emulator no longer reports a false exit code 0.
- `[esp+4]` is valid again, and labels such as `beach` or `fah` are no longer read as hexadecimal numbers.

## The tools IDEARM drives

IDEARM never contains or downloads TASM or MASM: they are proprietary, so you register the copy you already have
(**Help → Tool Doctor... → Add Tools Folder...**).

| You want to build | You need |
|---|---|
| 16-bit DOS programs | Your TASM + TLINK, or MASM 6.11 (`ML.EXE`, the 16-bit `LINK.EXE` and, on Linux, `DOSXNT.EXE`), and DOSBox |
| 32/64-bit Windows programs | NASM, GNU ld and GDB, for example from [MSYS2](https://www.msys2.org/) |
| 64-bit Linux programs | NASM, GNU ld (binutils) and GDB |

On Windows, install [DOSBox 0.74-3](https://www.dosbox.com/) (IDEARM prefers it, and also supports DOSBox-X and
DOSBox Staging), and the native tools with MSYS2:

```powershell
pacman -S --needed mingw-w64-ucrt-x86_64-nasm mingw-w64-ucrt-x86_64-binutils mingw-w64-ucrt-x86_64-gdb
```

On Ubuntu or Debian the `.deb` already asks apt for `dosbox`, `nasm`, `binutils` and `gdb`.

Start with **File → New Project...**, or open one of the examples in the source repository (`examples/hello`,
`examples/hello-input`, `examples/hello64-nasm`). The [user guide](../user-guide.md) explains every workflow, and
the [troubleshooting guide](../troubleshooting.md) explains each message.

## Known limitations

- The built-in emulator runs the 8086 and a few 80186 instructions, with no x87, no DOS file services and no
  graphics; debug those programs with Turbo Debugger or CodeView (`[debug] backend = "external"`). The Academic
  Center says so on the instructions it cannot run.
- Pause does not interrupt an emulated program that is waiting for a key.
- The code examples in the Academic Center keep the comments their author wrote, some in Spanish.
- On Linux, a program debugged with GDB reads an empty keyboard; run it with `Ctrl+F5` when it needs input.
- Native programs link only `kernel32` on Windows.
- With MASM in DOS, many include folders can exceed DOS's 126-character command line; TASM is not affected.
- macOS is not tested, and there is no packaged build for it.
- The Windows installer and the Linux packages are not signed.
